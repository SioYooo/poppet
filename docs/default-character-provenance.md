## Origin

The bundled blonde default character was generated by the repository owner
using OpenAI's ChatGPT image generation (`gpt-image`), including its automated
background removal, from the owner's own prompts. It is not hand-drawn
artwork, and earlier revisions of this record that described it as personally
created artwork were incorrect; this revision corrects that description based
on the owner's explicit statement on 2026-08-21.

The owner then gave this exact distribution authorization under the project's
former working name. The quotation is preserved verbatim as the owner
attestation:

> 确认：允许金发角色及其 KTT 派生图标随 KTT 公开源码及官方免费/付费商业安装包分发，并允许为 KTT 修改和格式转换；不允许第三方脱离 KTT 单独提取或复用。版权署名使用 Sioyoo。

The quoted `KTT` name is historical evidence only: it was the former working
name of the same project, not a current project or licence name. The owner
immediately renamed that project to Poppet, so the authorization applies to the
same source repository, application, and blonde asset chain under the current
Poppet name and `LicenseRef-Poppet-Scoped-Artwork` identifier.

## Generative-AI origin and C2PA disclosure

The tracked source anchor below embeds OpenAI's signed C2PA (Content
Credentials) manifest in a PNG `caBX` chunk: action `c2pa.created` with
software agent `gpt-image` 2.0 and
`digitalSourceType=trainedAlgorithmicMedia`, generated by "OpenAI Media
Service API" and signed for OpenAI OpCo, LLC under the SSL.com C2PA
certificate chain, together with `c2pa.converted` and watermark actions. The
manifest is retained intentionally as primary provenance evidence; it can be
independently inspected with any C2PA verifier.

The packaged derivatives listed below do not carry the manifest because the
Poppet pipeline re-encodes pixel data, but they remain derivatives of the
AI-generated source and are recorded as such. Release tooling rejects any
inventoried asset that carries a C2PA manifest while its recorded provenance
fails to disclose generative-AI origin.

## Unbundled black-haired reference

`F8B5D4B4-324B-487B-BFAC-E4A3A151D7E7.PNG`
(`cadc21e244e7681c6c664cec9ad4abd5fabd4018731d66b144845601aede31b4`) is an
owner-generated AI image, attested by the owner on 2026-08-24. It is covered by
the same `LicenseRef-Poppet-Scoped-Artwork` terms as the blonde source and stays
excluded from application packages; it exists in the repository as a reference
only.

**This record rests on a weaker evidence class than the blonde source, and that
difference is recorded rather than smoothed over.** The blonde source carries a
signed C2PA manifest in a `caBX` chunk naming OpenAI `gpt-image`, so its bytes
corroborate its record — and once refuted an earlier, wrong one. This file
carries no C2PA, XMP, or text chunk at all.

The absence is explained rather than unaccounted for, and the explanation is
checkable from the bytes. The owner states the file reached the repository from
an iPhone, and the two files' chunk sets match that account exactly:

| | Dimensions | Chunks | C2PA |
| --- | --- | --- | --- |
| blonde `5E700BDF` | 1024x1536 (a native gpt-image ratio) | `IHDR,caBX,IDAT,IEND` | present |
| black-haired `F8B5D4B4` | 1122x1402 (not a native output size) | `IHDR,sRGB,eXIf,pHYs,iDOT,IDAT,IEND` | absent |

`iDOT` is an Apple-proprietary chunk emitted by Apple's PNG encoder. Its presence
shows the file was re-encoded by an Apple image pipeline, which writes its own
chunk set and discards ancillary chunks it does not recognise — `caBX` among
them. The non-native dimensions show a crop or resize also occurred. The blonde
source, which never went through that path, kept its manifest. So the missing
manifest is the expected result of a known transfer mechanism, not an unexplained
anomaly.

That downgrades the absence from a red flag to a neutral fact. It does not
upgrade the record to byte-verified: a re-encode erases evidence of AI origin
and evidence of human origin identically, so these bytes cannot positively
confirm either.

Consequently the readiness checker's C2PA disclosure gate does not fire on this
file — it only forces disclosure for bytes that carry a manifest — and the
`OWNER_AI_GENERATED` value here is an owner statement, not a byte-verified fact.
If this file is ever republished, re-derived, or presented as evidence of
authorship, treat it accordingly. Removing the file from the repository remains
a valid alternative to carrying this attestation.
